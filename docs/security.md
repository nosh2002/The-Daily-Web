# אבטחה: תשתית, הזדהות והרשאות

מסמך זה מסביר איך האתר מזהה משתמשים ומגן על עצמו, ואילו קבצים אחראים לכל חלק.

## הזדהות
- **סיסמאות** נשמרות כ-hash של bcrypt (10 סבבים, עם salt אוטומטי) ב-`models/User.js`. הסיסמה עצמה לא נשמרת ואי אפשר לשחזר אותה. `toJSON` מסיר את ה-hash מכל תשובה.
- **התחברות** (`controllers/authController.js`): מחפשים משתמש לפי `username` (באותיות קטנות), משווים עם `bcrypt.compare`, ובהצלחה שומרים ב-session רק `id`, `username`, `displayName` ו-`role`.
- **הודעת שגיאה אחידה**: שם משתמש לא קיים וסיסמה שגויה מחזירים את אותה הודעה, כדי שלא ניתן לגלות אילו שמות משתמש קיימים.
- **הגבלת ניסיונות כושלים** (`middleware/loginRateLimiter.js`): עד 5 ניסיונות כושלים בדקה לכל כתובת IP. אחרי זה מוחזר 429 ללא בדיקת סיסמה. התחברות מוצלחת מאפסת את המונה.
- **Open redirect**: פרמטר `next` מתקבל רק אם הוא מתחיל ב-`/` (נתיב פנימי).

## Session
- נשמר ב-MongoDB באמצעות `connect-mongo` (קולקציית `sessions`), ולכן משתמש מחובר נשאר מחובר גם אחרי restart של השרת.
- הגדרות העוגייה ב-`server.js`: `httpOnly` (JavaScript בדפדפן לא יכול לקרוא אותה), `sameSite: lax`, תוקף שבוע, ו-`secure` כש-`NODE_ENV=production` (נשלחת רק ב-HTTPS). בייצור מאחורי proxy מופעל גם `trust proxy`.
- `SESSION_SECRET` מגיע מ-`.env` ואינו נשמר בגיט.

## הרשאות
- `middleware/auth.js`: `requireRole(...roles)` ממנו נגזרים `requireReporter` ו-`requireEditor`.
- מי שלא מחובר מופנה ל-`/login?next=...`, ובבקשות API (כתובות שמכילות `/api/`) מקבל 401 כ-JSON. מחובר בלי הרשאה מקבל 403.
- ההגנה נקבעת ב-`router.use(...)` בראש כל router רגיש, כך שאי אפשר לשכוח להגן על route חדש.
- ההרשאה נאכפת **בשרת**. הסתרת כפתור בלקוח היא נוחות בלבד.

## טיפול בשגיאות ולוגים
- `middleware/errorHandler.js`: `AppError` לשגיאות צפויות, `asyncHandler` להעברת שגיאות מפונקציות async, ו-`errorHandler` מרכזי שמחזיר JSON לבקשות API ועמוד שגיאה לשאר. שגיאה לא צפויה מציגה למשתמש הודעה כללית, והפרטים נכתבים ללוג.
- `utils/logger.js` כותב לקונסולה ול-`logs/app.log`. רמת הלוג נקבעת ב-`LOG_LEVEL` (`info`, `warn`, `error`).
- ב-`server.js` יש מטפלים גלובליים ל-`unhandledRejection` ול-`uncaughtException`.

## מגבלות ידועות
- המגביל נשמר בזיכרון התהליך: מתאפס ב-restart ואינו משותף בין כמה שרתים. בייצור נשתמש ב-Redis.
- אין הגנת CSRF עם טוקן (יש `sameSite: lax` בלבד), אין `helmet` לכותרות אבטחה, ואין אכיפת HTTPS בשרת עצמו.
- אין מנגנון נעילת חשבון או איפוס סיסמה.
